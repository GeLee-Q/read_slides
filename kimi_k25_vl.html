背景 ①

Kimi K2.5 是什么模型？

月之暗面（Moonshot AI）推出的视觉语言大模型，同时理解图像和文本。基于 DeepSeek MoE 架构，搭配 MLA 注意力机制。

🧠 超大 MoE 架构

数百个"专家"网络，每次只激活少数几个。大参数量 + 低激活计算量，实现高效推理。

🖼 视觉理解能力

Vision Tower 编码图像，MM Projector 将视觉特征对齐到语言空间，图文联合推理。这是 K2.5 区别于纯文本模型的核心差异。

Part 1.2

同集群 Colocate：MLA q-lora 配对修复 ↗ slime/pull/1753

🤔 什么是 MLA 的 q_lora？

当 q_lora_rank 启用时，MLA 的 Query/Key/Value 做低秩分解，拆成两个小矩阵。SGLang 在处理这类模型时，要求这两个权重在同一批 chunk 里到达，才能完成内部权重加载。

MLA 内部两个关键权重

q_a_proj

将 Query 压缩到低秩潜在空间的映射矩阵

⬇ 必须配对
kv_a_proj_with_mqa

将 Key/Value 压缩到同一低秩空间的映射矩阵

⚠ 为什么必须配对？
源码注释写明："to compatible with sglang implementation"。SGLang 在加载 MLA 权重时，需要 q_a_proj 和 kv_a_proj_with_mqa 同批（同一 chunk）到达才能完成权重更新。若分批发送，SGLang 无法正确加载，与量化无关。
📌 背景：分离集群路径（megatron_to_hf/__init__.py 的 _convert_to_hf_core()）已通过 _cached_tensors 实现此配对。PR #1753 为 Bridge 同集群路径的 _streaming_quantized() 补充同等机制。

Part 2

配置参数透传 — 让 Megatron 正确初始化 K2.5 ↗ slime/pull/1754

⚡ attention_softmax_in_fp32

K2.5 attention logits 值域大，BF16 softmax 易溢出为 ∞ / NaN，必须强制 FP32 以保证注意力权重的数值稳定性

⚖️ moe_router_bias_update_rate

K2.5 MoE 用 sigmoid 路由，router bias 动态更新使各 expert 接收 token 数均衡，防止部分 expert 空转或过载

📊 moe_aux_loss_coeff (α)

α 控制负载均衡优化力度；设为 0 时均衡项完全消失，MoE 退化为少数 expert 垄断所有 token

Part 3

VL Rollout 适配 — Processor API + 训练时 Token 扩展 ↗ slime/pull/1755

① Processor API 差异适配

K2.5 的 processor 接口与所有其他 VL 模型不兼容，原有通用调用方式直接报错。

❌ 标准模型（Qwen-VL、GLM-VL 等）

processor( text="描述图中内容", images=[img1, img2], videos=[video1], )

✅ K2.5 VL（Kimi 专属接口）

processor( text="描述图中内容", medias=[ {"type": "image", "image": img1}, {"type": "video", "video": video1}, ], )
解决方案：新增 call_processor() 统一入口
检测 processor 的 __call__ 签名是否有 medias 参数，有则用 K2.5 格式，否则用标准格式。

② 训练时 Image Token 扩展（K2.5 独有）

Rollout 生成时每张图只占 1 个 placeholder token（id=163605）；训练时须按实际图像网格大小展开为多个 token，才能正确计算每个位置的 loss。

Part 4

量化工具修复 — 视觉组件不能被量化 ↗ slime/pull/1757

📌 为什么视觉组件不能量化？

Vision Tower 和 MM Projector 是卷积 + 线性层结构，对 INT4/FP8 量化非常敏感，量化后图像理解能力会严重下降。

现有脚本针对 K2 已将 attention / embed / lm_head 加入 ignore 列表，实际只量化 MoE expert 线性层。VL 适配需额外豁免视觉组件。

修改的 3 个量化工具脚本

tools/convert_hf_to_fp8.py
tools/convert_hf_to_int4.py
tools/convert_hf_to_int4_direct.py

三个脚本都加了相同的 ignore 规则。

附加修复：K2.5 的量化配置嵌套在 config.json 的 text_config 层里，convert_kimi_int4_to_bf16.py 读取配置时也修了这个问题。
